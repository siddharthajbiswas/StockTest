# reference/ — the Python reference implementation

This is **not** a backend. Nothing serves it, nothing calls it at runtime, and
the app does not depend on it. It exists for one reason:

> It is the implementation the JavaScript engine is proven correct against.

`web/engine` is a port of `backtester/` + `strategies/`. A port is only
trustworthy if something independent says it matches, and that something is the
golden oracle in `golden/` — 23 backtest cases and 2 out-of-sample validation
cases, generated by running *this* code and frozen to JSON. Every TS test diffs
against those files at 1e-9 tolerance.

So this directory is test infrastructure with a long shelf life. Deleting it
would not break the app; it would remove the ability to prove the app is right.

## What's here

| File | Role |
|---|---|
| `service.py` | `EngineService` — wraps the engine as a library. The oracle's entry point. |
| `models.py` | Request/config validation (pydantic). Defines the request shape the goldens pin. |
| `oos_validation.py` | `run_validation` — holdout + walk-forward over the combo sweep. |
| `serialize.py` | `Result` → the JSON shapes the goldens record. |
| `analytics.py` | FIFO round-trip reconstruction, curve alignment. |
| `catalog.py` | Picker/timer/universe metadata; self-checks against the engine registries. |
| `tickers.py` | `TickerIndex` — symbol search and the ticker list. |
| `tests/` | Behavioural tests, called directly (no HTTP). |

`catalog.py` and `tickers.py` are also *build* inputs:
`tools/gen_web_metadata.py` exports them to JSON so the browser can serve the
catalog and ticker list without a server.

## History

Until Phase 8 this lived at `web/backend/` and was served by FastAPI on a Google
Cloud VM. The server is gone — `app.py`, the saved-strategy file store, the
background `ValidationRunner` job registry, and the HTTP tests were all deleted
along with it. What remained had nothing to do with being a backend, and the
name was actively misleading: it made load-bearing test infrastructure look like
dead code.

The old suite drove everything through a FastAPI `TestClient`. Its surviving
coverage now calls `EngineService` directly. What did not survive moved rather
than vanished:

- **saved-strategy store** → IndexedDB in the browser
  (`web/frontend/src/storage.js`), verified in Chrome.
- **HTTP error envelopes** → the worker protocol
  (`web/engine/test/worker.test.js`).

## Running things

```bash
.venv/bin/python -m pytest reference -q      # behavioural tests
.venv/bin/python -m pytest golden -q         # the oracle re-checks itself
.venv/bin/python tools/gen_golden.py         # regenerate the backtest goldens
.venv/bin/python tools/gen_validation_golden.py
```

**Regenerating the goldens is not a routine action.** It rebases the contract
the TS engine is measured against; do it only when a change to the numbers is
intended and reviewed. `tools/gen_golden.py --check` regenerates and diffs
without writing.

## If you change this code

Any change here is a change to the specification. The workflow is:

1. Make the change.
2. `pytest golden -q` — fails if the numbers moved.
3. If the move is intended, regenerate, and **check what changed** in the diff.
4. Re-run the TS suite (`cd web/engine && npm test`); it will now fail until the
   port is updated to match.

That order is deliberate: the oracle should notice before you do.
