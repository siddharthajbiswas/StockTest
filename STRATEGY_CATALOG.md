# Strategy Catalog — source of truth for the API & UI

This document is generated by reading the code directly (not the prose docs). It
is precise about **actual parameter names, types, and defaults** as they exist in
`strategies/pickers.py`, `strategies/timers.py`, `backtester/composite.py`,
`backtester/engine.py`, `backtester/result.py`, `backtester/tax.py`,
`backtester/universe.py`, and `walkforward.py`.

Two facts that apply everywhere, stated once:

- **How many names a strategy holds is NOT a picker parameter.** A picker's
  `select(ctx, universe, n)` receives `n` from the enclosing `Combo.top_n`. So
  "hold 15 stocks" is set on the `Combo`, not on the picker.
- **Look-ahead risk** comes from the data source, not the algorithm. The 3
  price-only pickers are honest over any period. The 7 fundamental pickers read a
  *current* snapshot (`data/fundamentals.csv`) that is not point-in-time, so
  their historical results carry look-ahead **and** survivorship bias — trust
  them only over a recent window near the snapshot date. All 10 timers are
  price-only.

## 1. The 10 Pickers

File: `strategies/pickers.py`. Registry: `PICKERS: dict[str, type[Picker]]`.
Price-only set: `PRICE_ONLY_PICKERS = {"momentum", "relative_strength", "random"}`.

Every picker implements `select(self, ctx: Context, universe: list[str], n: int) -> list[str]`,
returning the chosen tickers best-first, at most `n`.

### 1.1 `momentum` — `MomentumPicker`
- **Data:** price-only ✅ (no look-ahead)
- **Parameters:** `lookback: int = 126` (trading days; 126 ≈ 6 months)
- **Logic:** Ranks every candidate by its simple trailing return over the last
  `lookback` days and buys the strongest. In plain terms: "back the horses that
  have been winning lately." Pure trend-following — it says nothing about *when*
  to be in; a timer decides that.

### 1.2 `relative_strength` — `RelativeStrengthPicker`
- **Data:** price-only ✅
- **Parameters:** `benchmark: str = "SPY"`, `lookback: int = 126`
- **Logic:** Like momentum, but with a benchmark *filter*: it keeps only names
  whose trailing return actually **beats** the benchmark over the same window,
  ranked by how much they beat it. The filter is the real difference — in a broad
  downturn where nothing beats SPY it holds fewer names (possibly none), going
  defensive, whereas plain momentum would still buy the "least bad" losers.

### 1.3 `random` — `RandomPicker`
- **Data:** price-only ✅
- **Parameters:** `seed: int = 42`, `fraction: float | None = None`
- **Logic:** A control baseline that picks names at random, reshuffled each
  rebalance. By default it picks `n` names (a fair control against the ranked
  pickers). If `fraction` is set (e.g. `0.5`), it instead picks that share of the
  whole universe — the classic "monkey throwing darts at half the market" control
  used to check whether a real picker is adding anything.

### 1.4 `value_pe` — `ValuePicker`
- **Data:** fundamentals ⚠️ (look-ahead + survivorship risk — recent window only)
- **Column ranked:** `trailingPE`, `ascending=True`, `positive_only=True`
- **Logic:** Traditional value investing: buy the cheapest stocks by
  price-to-earnings ratio (lowest P/E first). Companies with a non-positive P/E
  are dropped before ranking, because a negative P/E isn't meaningfully "cheap."

### 1.5 `price_to_book` — `PriceToBookPicker`
- **Data:** fundamentals ⚠️
- **Column ranked:** `priceToBook`, `ascending=True`, `positive_only=True`
- **Logic:** Deep-value proxy: buy stocks trading cheapest relative to their
  accounting book value (lowest price-to-book first). "What am I paying per dollar
  of the company's net assets?"

### 1.6 `small_cap` — `SmallCapPicker`
- **Data:** fundamentals ⚠️
- **Column ranked:** `marketCap`, `ascending=True`, `positive_only=True`
- **Logic:** Small-cap tilt: buy the smallest companies by market
  capitalization, betting on the historical small-company return premium.

### 1.7 `quality_roe` — `QualityPicker`
- **Data:** fundamentals ⚠️
- **Column ranked:** `returnOnEquity`, `ascending=False`, `positive_only=False`
- **Logic:** Quality investing: buy the companies that generate the most profit
  per dollar of shareholder equity (highest return-on-equity first) — profitable,
  efficient businesses. Negatives are *not* filtered out here, so a name can still
  be ranked (just poorly) even with negative ROE.

### 1.8 `growth_revenue` — `GrowthPicker`
- **Data:** fundamentals ⚠️
- **Column ranked:** `revenueGrowth`, `ascending=False`, `positive_only=False`
- **Logic:** Growth investing: buy the companies whose sales are growing fastest
  (highest revenue growth first).

### 1.9 `high_dividend` — `DividendPicker`
- **Data:** fundamentals ⚠️
- **Column ranked:** `dividendYield`, `ascending=False`, `positive_only=True`
- **Logic:** Income investing: buy the highest dividend-yielding stocks. Names
  paying no dividend are dropped, since a zero yield isn't an income holding.

### 1.10 `earnings_surprise` — `EarningsSurprisePicker`
- **Data:** fundamentals ⚠️
- **Column ranked:** `earningsSurprisePct`, `ascending=False`, `positive_only=False`
- **Logic:** Post-earnings-drift: buy the companies that most recently beat their
  earnings estimates by the widest margin, betting the good news keeps pushing the
  price up for a while.

**Note on the 7 fundamental pickers' "parameters":** unlike the price pickers,
they take **no `__init__` arguments** — you instantiate them bare, e.g.
`ValuePicker()`. What's configurable is set as class attributes on
`FundamentalPicker`: `field: str`, `ascending: bool`, `positive_only: bool`. The
base `select` ranks `data/fundamentals.csv[field]` restricted to the current
universe, optionally dropping non-positive values, and returns the top `n`. They
raise `FileNotFoundError` at `initialize` if the snapshot is missing.

## 2. The 11 Timers

File: `strategies/timers.py`. Registry: `TIMERS: dict[str, type[Timer]]`. All
timers are **price-only**. Each implements
`want_long(self, ctx, ticker, *, held: bool, entry_price: float | None) -> bool`
— asked once per basket name per day. `held` = do we currently own it (lets a
timer use different enter vs. exit thresholds), `entry_price` = the close we
opened at (for stop-losses).

### 2.1 `buy_hold` — `BuyHoldTimer`
- **Parameters:** none
- **Logic:** Always wants to be long. Paired with a picker, this just holds the
  picked basket and only changes it when the picker rebalances. The timing
  baseline — use it to isolate the picker's contribution.

### 2.2 `ma_cross` — `MaCrossTimer`
- **Parameters:** `fast: int = 50`, `slow: int = 200`
- **Logic:** The classic "golden cross" trend filter — stay long only while the
  50-day average price is above the 200-day average, i.e. while the medium-term
  trend is up. Goes flat when the fast average dips below the slow one.

### 2.3 `rsi` — `RsiTimer`
- **Parameters:** `period: int = 14`, `oversold: float = 30.0`, `exit_level: float = 70.0`
- **Logic:** Mean-reversion on the Relative Strength Index. **Enter** when the
  stock is oversold (RSI ≤ 30) — beaten down and due to bounce — and **hold**
  until it recovers back above 70, then exit. The two different thresholds
  (hysteresis) stop it from flickering in and out around a single level.

### 2.4 `macd` — `MacdTimer`
- **Parameters:** `fast: int = 12`, `slow: int = 26`, `signal: int = 9`
- **Logic:** Momentum confirmation via MACD: stay long while the MACD line (fast
  minus slow moving average) sits above its own signal line — i.e. while upward
  momentum is accelerating. Flat otherwise.

### 2.5 `bollinger` — `BollingerTimer`
- **Parameters:** `window: int = 20`, `k: float = 2.0`
- **Logic:** Volatility-band mean reversion. **Buy** when price drops to the
  lower Bollinger band (`k` standard deviations below the `window`-day average) —
  unusually cheap — and **hold** until it climbs back up to the upper band, then
  sell. Buy-low-sell-high within a range.

### 2.6 `momentum12` — `MomentumTimer`
- **Parameters:** `lookback: int = 252`, `threshold: float = 0.0`
- **Logic:** An absolute 12-month momentum gate: only be long a name whose
  trailing-`lookback`-day return is above `threshold` (default: positive). A
  simple "is this actually in an uptrend over the past year?" filter.

### 2.7 `dual_momentum` — `DualMomentumTimer`
- **Parameters:** `lookback: int = 252`, `benchmark: str = "SPY"`
- **Logic:** Requires **both** absolute and relative strength: be long only when
  the name is up over the lookback **and** beating the benchmark over the same
  window. Stricter than `momentum12` — it won't hold something that's rising but
  lagging the market.

### 2.8 `turtle` — `TurtleBreakoutTimer`
- **Parameters:** `entry_window: int = 252`, `exit_window: int = 100`
- **Logic:** Donchian-channel breakout (the "Turtle Traders" rule). **Buy** when
  price makes a new high versus the prior `entry_window` days (a fresh 52-week
  high) and **hold** until it falls below the lowest close of the last
  `exit_window` days. Ride strong breakouts, cut them when the trend rolls over.

### 2.9 `vol_reversion` — `VolReversionTimer`
- **Parameters:** `short: int = 20`, `long: int = 100`, `spike: float = 1.5`
- **Logic:** Bets that panic reverts. **Enter** when short-term realized
  volatility spikes to at least `spike`× its longer-run level (a fear event), and
  **hold** until volatility calms back to its baseline. "Buy when others are
  fearful, sell once things settle."

### 2.10 `trend_stop` — `TrendStopTimer`
- **Parameters:** `ma_window: int = 200`, `stop: float = 0.08`
- **Logic:** Trend-following with a hard safety stop: be long while price is above
  its `ma_window`-day moving average, **but bail immediately** if the position
  falls more than `stop` (default 8%) below the price you entered at — regardless
  of the trend. The stop-loss caps the damage on any single name.

### 2.11 `trend_switch` — `TrendSwitchTimer` (manual mode only)
- **Parameters:** `signal: str = "SPY"`, `n: int = 175`, `band: float = 0.03`,
  `risk: str = "SSO"`, `safe: str = "IEF"` (`risk`/`safe` are comma-separated
  ticker lists, equal-weighted)
- **Logic:** One trend signal switches the whole basket between a risk side and
  a safe side. Every trading day, on the close:
  `margin = signal_close / mean(last n signal closes, today included) - 1`.
  The first evaluation sets `state = margin > 0`; afterwards the state turns
  on above `+band`, off below `-band`, and is otherwise kept (hysteresis). On ->
  the `risk` tickers are long; off -> the `safe` ones. Evaluated once per date and
  shared by every ticker. Until the first evaluation succeeds (fewer than `n`
  closes) nothing is held. Built for manual mode with tickers = risk + safe, e.g.
  SSO (2x S&P 500) + IEF (7-10y Treasuries) — the site's "2× S&P trend switch
  (CA)" preset. Same rule as `research/lab/families/verify_lev_robust.py::Trend`
  (`check="D"`, `lag=0`, `ma="sma"`). Leverage magnifies losses.
- **Not swept:** the combo sweeps (`grid_combos.py`, `walkforward.py`, the
  out-of-sample validator) iterate `SWEEP_TIMERS` — every timer except the
  manual-only ones in `MANUAL_ONLY_TIMERS` — since a picker's basket never
  contains its named tickers.

## 3. Combo — wiring a picker to a timer

Class: `backtester.composite.Combo` (a `Strategy`). This is the object the API
runs. It refreshes the picker's basket on a rebalance cadence, then every day asks
the timer which basket names to be long, and holds the intersection
equal-weighted.

```python
Combo(
    picker: Picker,
    timer: Timer,
    top_n: int = 20,              # how many candidates the picker returns
    rebalance: str = "M",        # "D" daily | "W" weekly | "M" monthly | "Q" quarterly
)
```

Behavior (from `on_day`): on a new rebalance period the picker reselects `top_n`
names; every day the timer is polled per basket name (`want_long`); the portfolio
liquidates anything it holds that's no longer wanted and equal-weights
(`1/len(longs)`) the names it does want, **rewriting weights only when the held
set actually changes** to limit commission churn. Entry prices are tracked per
name so stop-style timers work.

Importable from the package root: `from backtester import Combo`. The picker/timer
classes come from `strategies.pickers` / `strategies.timers` (or their registries
`PICKERS` / `TIMERS`, which map the short string name → class).

### Running a SINGLE combo backtest end-to-end (the API path)

```python
from backtester import Backtest, Combo, TaxPolicy, load_prices
from strategies.pickers import PICKERS
from strategies.timers import TIMERS

# 1. Load price data: {ticker: DataFrame[Open,High,Low,Close,Volume]}
prices = load_prices(
    tickers=None,          # None = every ticker CSV in data/; or a list like ["AAPL","MSFT","SPY"]
    start="2010-01-01",   # "YYYY-MM-DD" | None
    end="2026-12-31",     # "YYYY-MM-DD" | None
)

# 2. Build the strategy
strat = Combo(PICKERS["momentum"](), TIMERS["turtle"](), top_n=15, rebalance="M")

# 3. Run one backtest
result = Backtest(
    strat,
    prices=prices,
    cash=100_000.0,
    commission_pct=0.0005,                       # 5 bps of trade value
    slippage_pct=0.0005,                         # 5 bps spread cross
    tax_policy=TaxPolicy(short_term_rate=0.35, long_term_rate=0.15),
).run()

result.summary()
```

**Exact `Backtest.__init__` signature** (`backtester/engine.py`):

```python

    prices: dict[str, pd.DataFrame] | None = None,   # pass this OR market=

    commission_pct: float = 0.0,                      # fraction of trade value, 0.001 = 10 bps

```

Pass **either** `prices=` (engine builds a `MarketData` for you) **or** a prebuilt

## 4. The Result object

Class: `backtester.result.Result` (returned by `Backtest.run()`). `TRADING_DAYS = 252`.

### Stored fields
| Field | Type | Contents |
|-------|------|----------|
| `equity` | `pd.DataFrame` | index = `date` (DatetimeIndex); columns = `cash`, `holdings`, `total`. One row per trading day. `taxes_paid` is already deducted along this curve; `terminal_tax` is **not**. |
| `trades` | `pd.DataFrame` | index = `date`; columns = `ticker`, `side` ("BUY"/"SELL"), `shares`, `price`, `value`, `commission`. Empty DataFrame if no trades. |
| `starting_cash` | `float` | Initial cash. |
| `taxes_paid` | `float \| None` | Capital-gains tax settled *in-loop* (annually), already reflected in the equity curve. `None` when `tax_policy` was not supplied. |
| `terminal_tax` | `float \| None` | Tax on the final partial year's realized gains **plus** a liquidation tax on all remaining unrealized gains, as if everything were sold on the last day. NOT deducted from `equity`; folded only into the after-tax metrics below. `None` without a tax policy. |

### Computed properties (pre-tax)
| Property | Type | Meaning |
|----------|------|---------|
| `final_value` | `float` | `equity["total"].iloc[-1]`. |
| `total_return` | `float` | `final_value / starting_cash - 1`. |
| `cagr` | `float` | Annualized compound growth (365.25-day years). |
| `daily_returns` | `pd.Series` | Daily pct-change of `total`, NaNs dropped. |
| `sharpe` | `float` | Annualized Sharpe, `sqrt(252) * mean/std` of daily returns (risk-free = 0). `0.0` if flat/empty. |
| `max_drawdown` | `float` | Worst peak-to-trough of `total` (negative number). |

### Computed properties (after-tax — full liquidation)
These apply `terminal_tax` on top of the in-loop `taxes_paid` so a churn-heavy
strategy and a defer-forever buy-and-hold are comparable on a fully-after-tax
basis. When `tax_policy` was `None`, `terminal_tax`/`taxes_paid` are `None` and
these fall back to the pre-tax numbers (the `or 0.0` guards).

| Property | Type | Meaning |
|----------|------|---------|
| `after_tax_final_value` | `float` | `final_value - terminal_tax`. |
| `after_tax_total_return` | `float` | After-tax return vs. starting cash. |
| `after_tax_cagr` | `float` | Annualized after-tax compound growth. |
| `total_tax` | `float` | `taxes_paid + terminal_tax` — the total tax drag in dollars. |

**Tax drag** for the UI = `total_tax` (dollars), or `cagr - after_tax_cagr`
(annualized percentage points lost to tax).

### Methods
- `summary() -> None` — prints the headline block (period, returns, CAGR,
  Sharpe, max drawdown, trade count, commission, and — when taxes are on — taxes
  paid / terminal / total / after-tax final / after-tax return / after-tax CAGR).
- `trades_by_day() -> None` — prints the trade blotter grouped by day.
- `save(out_dir) -> None` — writes `equity.csv` and `trades.csv` to `out_dir`.

## 5. Universe selection & validation harness

### 5.1 Choosing the universe (full dataset vs. `sp500-pit`)

The universe choice is expressed by **how you build the `MarketData`**. The
convenience wrapper both `grid_combos.py` and `walkforward.py` use:

```python
# grid_combos.build_market
build_market(prices: dict[str, pd.DataFrame], universe: str) -> MarketData
#   universe = "all"        -> MarketData(prices)                  (every ticker with data)
#   Callers pass universe_tickers(): data/ minus backtester.data.UNIVERSE_EXCLUDE
#   (SSO, IEF — loadable by name in manual/menu mode, never pickable).
#   universe = "sp500-pit"  -> point-in-time S&P 500 membership filter applied
```

Under the hood the `sp500-pit` path calls (`backtester/universe.py`):

```python
load_membership(path: Path | str = CONSTITUENTS_PATH) -> pd.Series
#   Series indexed by snapshot date, values = frozenset of tickers.
#   Default path: data/sp500_constituents.csv

members_by_calendar(
    membership: pd.Series,
    calendar: pd.DatetimeIndex,
    restrict_to: set[str] | None = None,   # intersect with tickers you actually have
) -> list[frozenset]                        # one member-set per calendar day (as-of join)
```

...and feeds the result to the market constructor:

```python
MarketData(prices: dict[str, pd.DataFrame], members_by_day: list[frozenset] | None = None)
#   members_by_day=None  -> selectable universe = everything tradable that day ("all")
#   members_by_day=[...]  -> selectable universe restricted to that day's index members
```

The membership filter restricts only what a strategy may **select** each day
(`ctx.universe`); a position can still be **sold** after its name leaves the
index. It corrects *membership look-ahead only* — it does **not** resurrect
delisted companies (free data lacks their prices), so `sp500-pit` results remain
optimistically biased. A full correction needs paid PIT data (CRSP / Sharadar /
Norgate).

**For a single API run with survivorship control:** build the market yourself and
pass it as `market=`:

```python
from grid_combos import build_market
market = build_market(prices, "sp500-pit")
result = Backtest(strat, market=market, slippage_pct=0.0005,
                  tax_policy=TaxPolicy()).run()
```

### 5.2 Walk-forward / holdout validation (`walkforward.py`)

Two out-of-sample validation modes. **Important for the API layer:** these are
currently **CLI functions that take an `argparse.Namespace`**, not clean keyword
APIs. `holdout(args)` and `walkforward(args)` each expect an object with the
attributes below; both call `run_all_curves(args)` first to run every combo once
and capture its equity curve. To drive them programmatically, construct a
namespace (e.g. `argparse.Namespace(...)` or a `SimpleNamespace`) with **all** of
these fields, or shell out to the CLI.

```python
run_all_curves(args) -> tuple[pd.DatetimeIndex, dict[(picker,timer) -> np.ndarray], np.ndarray]
#   (dates, {combo: daily_total_equity_curve}, spy_curve) — all net of commission+slippage+tax
holdout(args) -> None       # prints the holdout report
walkforward(args) -> None   # prints the walk-forward report
```

**Required `args` attributes** (names, types, defaults from the CLI parser):

| Attribute | Type | Default | Used by |
|-----------|------|---------|---------|
| `mode` | str | — | `"holdout"` or `"walkforward"` |
| `tickers` | list[str] \| None | `None` (all) | both |
| `start` | str | `"2000-01-01"` | both |
| `end` | str | `"2026-12-31"` | both |
| `universe` | str | `"sp500-pit"` | both (`"all"` or `"sp500-pit"`) |
| `price_only` | bool | `False` | both (restrict to momentum/relative_strength/random) |
| `split` | str | `"2016-01-01"` | holdout — train/test boundary |
| `train_years` | int | `5` | walkforward — trailing window to rank on |
| `step_years` | int | `1` | walkforward — out-of-sample chunk earned per step |
| `cash` | float | `100_000.0` | both |
| `commission_pct` | float | `0.0005` | both |
| `slippage_pct` | float | `0.0005` | both |
| `st_rate` | float | `0.35` | both — short-term cap-gains rate |
| `lt_rate` | float | `0.15` | both — long-term cap-gains rate |
| `jobs` | int | `cpu_count()-1` | both — parallel worker processes |

**Modes, in plain terms:**

- **holdout** — splits the timeline at `split`. Ranks all combos by their return
  on the *train* window, then reports how those same combos do on the *untouched
  test* window: the rank persistence (Spearman train-vs-test; ≈0 means in-sample
  skill was noise), how many top-10 combos beat SPY out-of-sample, and the single
  honest "pick the train winner, judge it once on test" result.

- **walkforward** — rolls through time: at each step it picks the combo with the
  best trailing `train_years` return, earns the next `step_years` with it
  out-of-sample, and chains those OOS chunks into one track record versus SPY
  buy-and-hold. Simulates actually running the system with only past data at each
  decision. (Caveat noted in-code: switching baskets between windows ignores the
  tax cost of the switch, slightly flattering the adaptive strategy.)

CLI equivalents:

```bash
python walkforward.py holdout --split 2016-01-01 --price-only
python walkforward.py walkforward --train-years 5 --step-years 1 --price-only
```

## Appendix — string name → class registries (for the API)

```python
from strategies.pickers import PICKERS, PRICE_ONLY_PICKERS
from strategies.timers import TIMERS

PICKERS.keys()  = momentum, relative_strength, random, value_pe, price_to_book,
                  small_cap, quality_roe, growth_revenue, high_dividend,
                  earnings_surprise
PRICE_ONLY_PICKERS = {momentum, relative_strength, random}
TIMERS.keys()   = buy_hold, ma_cross, rsi, macd, bollinger, momentum12,
                  dual_momentum, turtle, vol_reversion, trend_stop
```

Each registry maps the stable short name (the same string the CLI `--pickers` /
`--timers` flags accept, and a good stable id for API/UI) to the class. Instantiate
bare — `PICKERS["momentum"]()` — to get library defaults, or pass the constructor
parameters documented in §1–§2 to customize.
